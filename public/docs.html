Complete documentation · users · development · learning

vDownloader,
explained from end to end.

This page contains the project's functional and technical documentation. It is written for users, junior developers, and students who want to understand a real application built with Node.js, JavaScript, HLS, and FFmpeg.

Responsible use. Use the application only with content you have the right to download, and follow each provider's terms and applicable law. Adult providers are intended only for people aged 18 or older.

Project summary

BackendNode.js ≥ 20

Framework-free HTTP server with ES modules.

MediaFFmpeg + HLS.js

Video preparation, audio transcoding, and HLS playback.

Providers4 supported sites

YouTube, XVideos, Pornhub, and XNXX with authorized domains.

StateLocal persistence

Recoverable queue, retries, and temporary files.

01 · Installation

Quick start

On Linux, vDownloader uses system-managed FFmpeg and yt-dlp. Windows development environments may use the local binaries installed through npm.

  1. Install Node.js 20 or later.

    Check the version with node --version.

  2. Install the Linux tools.
    sudo apt install -y ffmpeg pipx
pipx install yt-dlp
  3. Install the Node.js dependencies.
    YOUTUBE_DL_SKIP_DOWNLOAD=true YOUTUBE_DL_SKIP_PYTHON_CHECK=1 npm ci
  4. Start the service.
    npm start
  5. Open the application.
    http://localhost:5177

Development with automatic restart

npm run dev

Installing yt-dlp on Windows

youtube-dl-exec installs a local yt-dlp executable. If its installer cannot find Python, skip that check; the Windows binary is self-contained.

$env:YOUTUBE_DL_SKIP_PYTHON_CHECK = '1'
npm install

02 · Usage

User guide

  1. Paste a supported URL.

    Individual public videos from YouTube, XVideos, Pornhub, and XNXX are supported.

  2. Select Analyze.

    The application obtains the provider, title, duration, thumbnail, and qualities.

  3. Review the preview.

    HLS uses a restricted local proxy to handle CORS.

  4. Optional: enable trimming.

    Use the timeline, time fields, or current player position.

  5. Choose a quality.

    The estimated size is adjusted to the selected range.

  6. Wait for preparation.

    The panel shows queue status, progress, attempts, and remaining time.

  7. Download the MP4.

    The complete file supports resumable downloads.

Temporary links. If a CDN link expires, the job analyzes the original URL again and looks for the same quality.

Job administration

The panel includes individual and bulk Restart actions. They preserve source, provider, quality, trim range, and Identity protection; remove previous output; clear progress and errors; refresh signed URLs; and return jobs to the queue. Status, provider, and date filters, expired-file cleanup, storage figures, bounded job-event history, and administrative audit are available in the same panel.

On localhost, no token is required while ADMIN_TOKEN is empty. For remote access, enter the configured token in the Job administration section. The browser stores it only in sessionStorage for the current tab.

Current scope. Local mode manages all jobs as the local administrator. Optional remote profiles provide owner isolation and user/admin roles, but there is no registration, password recovery, MFA, or external single sign-on.

02.1 · Editor

Trim and transcode a local video

The editor supports MP4, M4V, MOV, and WebM. After you select a file, the browser creates a preview with a local blob: URL; the file has not yet been sent to the server.

  1. Select the video.

    The format, size, and duration are validated.

  2. Set the start and end.

    Use the two timeline handles, time fields, or current player position.

  3. Choose the output profile.

    Select MP4, MOV, WebM, or MKV and a compatible video/audio codec pair.

  4. Optional: protect identities.

    Enable the feature, adjust margin and intensity, detect faces, and review the preview.

  5. Select Export.

    Only then is the temporary file uploaded. The button shows the uploaded percentage.

  6. Wait for the job.

    The export uses the same queue, progress, cancellation, persistence, and panel as remote downloads.

  7. Download the result.

    FFmpeg produces the selected allowlisted profile: H.264/H.265 with AAC or Opus, or VP9 with Opus, in a compatible container.

FormatsMP4, M4V, MOV, and WebM.
OutputsMP4/MOV with H.264 or H.265 plus AAC; WebM with VP9 plus Opus; MKV with compatible H.264/H.265/VP9 and AAC/Opus combinations.
DurationBetween 1 second and 12 hours.
Size2 GB by default; configurable with MAX_UPLOAD_GB.
RetentionThe source is removed when the job is deleted or expires.
Temporary does not mean immediate deletion. The source is retained for the life of the job so an administrator can restart it. Its path is never exposed, and incomplete uploads are removed automatically.

Identity protection

This feature automatically locates all faces in the selected range. MediaPipe Tasks Vision and the BlazeFace model are served by vDownloader and run in the browser: no frame is sent to an external recognition service.

  1. Enable Identity protection.

    The panel appears inside the local editor.

  2. Adjust the margin.

    Expand each region to cover the head and imprecise movement. The default is 40%.

  3. Adjust the intensity.

    A larger block produces stronger pixelation.

  4. Select Detect faces.

    The browser analyzes up to four samples per second, with a maximum of 900, and displays progress.

  5. Select anonymous people.

    Every spatial track is labeled Person 1, Person 2, and so on. This is tracking, not biometric recognition.

  6. Correct individual points.

    Add a missed region, select it on the canvas, drag it, resize it from the lower-right corner, or delete only that sampled point.

  7. Review the full path.

    The editor plays the complete protected range. Export remains blocked until the user confirms the visual review.

  8. Export with protection.

    FFmpeg creates a moving temporal mask and applies pixelize only to selected and manually corrected regions.

Reinforced tracking joins each face's current position to its next position to cover movement between samples. It also preserves coverage for up to 1.5 seconds when a face is briefly lost because of a turn or occlusion. The result is intentionally conservative: fast movement may pixelate a larger area to reduce exposure.

This is not an absolute guarantee. A small, turned, covered, or poorly lit face may be missed. Review the final exported video before sharing it. The feature does not anonymize voices, tattoos, license plates, backgrounds, metadata, or other personal signals.

The browser does not send all boxes in a header or URL. It first registers normalized coordinates with POST /api/identity-tracks and receives a temporary, single-use UUID. Tracking is attached to the job and stored in jobs.json to support restarts; it contains no images, facial templates, or biometric identifiers.

02.2 · Audio

Trim, join, and transcode local audio

The audio tool supports one to twenty MP3, M4A, AAC, WAV, FLAC, OGG, and Opus inputs. The browser creates local previews first; sources are sent to the server only after the user selects Export audio.

  1. Select the audio files.

    Each extension, MIME type, size, and browser-readable duration is validated.

  2. Trim every source.

    Select an item from the ordered list and use the shared timeline to set that source's own start and end.

  3. Set the join order.

    Move items earlier or later, or remove an item before export.

  4. Choose the output.

    Select a compatible format/codec pair. Lossy codecs offer 96, 128, 192, 256, or 320 kbps.

  5. Export.

    A single source uses the binary endpoint. Multiple sources use a bounded streaming envelope and enter the same persistent queue.

  6. Download or resume.

    The final typed output supports HTTP byte ranges.

InputMP3, M4A, AAC, WAV, FLAC, OGG, and Opus.
OutputMP3/MP3, M4A/AAC, OGG/Vorbis or Opus, Opus/Opus, FLAC/FLAC, or WAV/PCM signed 16-bit little endian.
Limits1–20 sources; every range lasts at least one second; combined selected duration is at most 12 hours.
LifecycleSame quota, ownership, queue, restart, cancellation, expiration, cleanup, and panel as video.
Server-owned profiles. The browser chooses only an allowlisted format, codec, and bitrate combination. It cannot send a raw FFmpeg argument, output extension, or filesystem path. The first compatible stream from each input is normalized to 48 kHz stereo before concatenation.
Preview compatibility. A browser may not preview every accepted codec even when FFmpeg can transcode it. If duration cannot be read, convert the source to WAV, MP3, or M4A first or use another current browser.

03 · Design

Architecture

BrowserHTML · CSS · app.js · HLS.js
HTTP
ServerAPI · queue · persistence
HTTPS
ProviderPublic page and CDN

FFmpegVideo · audio · trim · join
  • Framework-free backend: makes it easier to study node:http directly.
  • Modular providers: each site validates and analyzes its own structure.
  • Remote video without transcoding: preserves quality and reduces CPU usage when the source is already H.264.
  • Bounded local video profiles: only compatible MP4/MOV/WebM/MKV and H.264/H.265/VP9 plus AAC/Opus combinations are accepted.
  • Bounded audio profiles: local audio uses explicit input, output, codec, and bitrate allowlists.
  • Streaming joins: multi-audio bytes are streamed to UUID-owned paths and concatenated after sample normalization.
  • SSRF defense: only explicitly authorized pages and CDNs are accepted.

07 · HTTP contract

HTTP API

POST/api/analyze

Input: { "url": "https://..." }. Output: provider, title, duration, and qualities with opaque selectionId and previewUrl values. Signed CDN URLs are never returned.

POST/api/jobs

Creates a job and responds with HTTP 202.

{
  "selectionId": "uuid-returned-by-analyze",
  "start": 30,
  "end": 90
}
POST/api/upload-jobs

Receives local video as a binary body. Requires Content-Length, x-vdownloader-upload: 1, encoded name/duration/range headers, and allowlisted x-video-format, x-video-codec, and x-video-audio-codec values. Responds with HTTP 202 and never returns an internal path.

POST/api/audio-jobs

Receives one audio source as a binary body. Requires x-vdownloader-audio: 1, regular x-upload-* headers, x-audio-format, x-audio-codec, and a lossy bitrate when applicable.

POST/api/audio-join-jobs

Receives 2–20 ordered sources through application/vnd.vdownloader.audio-join. A four-byte metadata length precedes at most 64 KiB of versioned JSON and the declared binary sources. Requires x-vdownloader-audio-join: 1. Bytes stream to UUID-owned files; complete media is never buffered in memory.

POST/api/identity-tracks

Input: pixelate method, duration, block size, and up to 900 samples with normalized boxes. Requires x-vdownloader-identity: 1. Returns identityTrackId, an in-memory UUID that expires after 30 minutes and is consumed when the upload is created.

GET/api/jobs

Lists the authenticated user's jobs and statistics. Administrators can see all jobs.

GET/api/jobs/:id

Returns status, progress, and retry/event history when the caller owns the job or is an administrator.

DELETE/api/jobs/:id

Cancels or deletes an owned job. Administrators can manage every job.

POST/api/jobs/:id/restart

Restarts one job, preserves its parameters, and responds with HTTP 202. Requires x-vdownloader-admin: 1 and administrator authorization.

POST/api/admin/jobs/restart

Bulk-restarts up to 100 job IDs. Requires x-vdownloader-admin: 1 and an administrator profile.

POST/api/admin/jobs/cleanup

Removes expired jobs and their temporary files when called with { "scope": "expired" }.

GET/api/admin/audit

Returns the bounded administrative audit trail for authorized administrators.

GET / HEAD/api/jobs/:id/download

Streams the completed typed video or audio output and supports ranges with HTTP 206.

GET/api/media/:id

Opaque proxy for MP4, manifests, segments, and HLS keys. The UUID is resolved only in memory.

GET/api/health

vDownloader diagnostics: version, uptime, FFmpeg, yt-dlp, queue, retention, storage, and the caller's role. Responds with HTTP 503 when a dependency is missing.

Remote authentication. When remote mode is enabled, API requests use Authorization: Bearer <token>. Tokens and roles are configured with ACCESS_TOKENS_JSON. A direct local loopback request is an administrator session. A request forwarded from a remote address by a trusted local proxy remains remote and must authenticate; non-HTTPS remote requests receive HTTP 426. Legacy ADMIN_TOKEN can still protect local administrator actions when configured.

States

queuedWaiting in the queue.
processingFFmpeg is active.
retryingRefreshing or waiting.
restartingStopping the previous execution before restarting it.
readyFile available.
cancelledCancelled.
errorTerminal failure.

09 · Integrations

Provider architecture

A provider declares its identity, page rules, CDN domains, HTTP referer, and parser.

The current registry contains youtube, xvideos, pornhub, and xnxx. Each integration restricts both the source page and its authorized CDN hosts.

YouTube and adaptive formats

providers/youtube.js runs the system yt-dlp on Linux and the package's local binary in other development environments. The provider selects an H.264 track for each resolution and attaches the best M4A track when YouTube delivers audio separately. The job validates both googlevideo.com URLs, keeps them private, refreshes them together, and uses FFmpeg to create one MP4.

Maintenance. YouTube changes frequently. If public videos can no longer be analyzed, update the dependencies to obtain a recent yt-dlp version.
npm run update:yt-dlp

High resolutions display video + audio. vDownloader downloads both signed tracks, refreshes them together if they expire, and produces an MP4 with H.264 and AAC-LC. Compatibility is prioritized up to 1080p; 1440p/4K often depends on VP9 or AV1 and is not offered when it would require expensive transcoding.

10 · State

Persistence, queue, and storage

  • jobs is the in-memory map, and jobQueue contains pending IDs.
  • jobs.json is written through a temporary file and atomic rename.
  • Recovered active remote jobs return to queued and refresh their links.
  • Local jobs retain relative UUID source names and rebuild paths inside JOB_DIR.
  • Joined audio retains ordered source names and per-source clips; recovery requires every source.
  • Video/audio container and codec IDs are revalidated while restoring state; persisted data cannot choose an arbitrary encoder, extension, or content type.
  • Ready files and every local source expire according to JOB_TTL_MINUTES.
  • The quota counts ready outputs and all temporary sources, removing old terminal jobs first.
  • Active or queued jobs are never removed because of expiration.

Observability

The server emits JSON events such as server_started, job_ready, job_failed, job_restarted_by_admin, and expired_jobs_cleaned. On Linux, they can be queried and filtered directly with journalctl. The panel consumes /api/health and displays FFmpeg and yt-dlp status.

11 · Browser

Frontend

Uses native JavaScript, DOM APIs, and CSS; no compiler is required.

  • Languages: Spanish and English strings live in public/i18n.js; the device-local choice is stored in localStorage.
  • HLS.js: remote HLS playback.
  • Local preview: video and audio use URL.createObjectURL; references are revoked when files change or the tab closes.
  • Trimming: converts HH:MM:SS to seconds and shares synchronized controls across media flows.
  • Video output: container selection rebuilds compatible video and audio codec choices.
  • Audio joining: every source retains its own range and visible order; lossless profiles disable bitrate.
  • Upload: XMLHttpRequest reports binary progress for single and streaming join bodies.
  • Polling: active jobs are checked every 1.5 seconds, the global panel every 5 seconds, overlapping panel reads are coalesced, hidden tabs pause panel polling, and HTTP 429 waits for Retry-After without declaring a false job failure.
  • Token: remains in sessionStorage, never in the URL.
  • History: stores IDs in localStorage and validates them.
  • Accessibility: labels, ARIA attributes, and semantic buttons.

14 · Compliance

Licenses, CDNs, and local use

A CDN is not a project library: it is the external network from which each provider delivers media. YouTube uses googlevideo.com; XVideos uses xvideos-cdn.com; Pornhub uses phncdn.com; and XNXX uses xnxx-cdn.com. vDownloader allows only these explicitly registered hosts.

Why links expire

Media URLs often contain signatures, tokens, and expiration dates. When they stop working, it does not mean that a library lost its license. vDownloader retains the original page, analyzes it again, and refreshes video and audio tracks together. These URLs exist only in memory: the browser uses opaque UUIDs, and the persistent index does not store CDN signatures.

What localhost means

Running vDownloader on localhost reduces service exposure, but does not grant rights to videos or remove terms of use, regional restrictions, or copyright. The application needs Internet access to query provider pages and CDNs.

The interface is self-contained: HTML, CSS, JavaScript, favicon, system fonts, HLS.js, MediaPipe, its WASM binaries, and BlazeFace are served locally. It does not use Google Fonts or a library CDN. Thumbnails and media still come from providers because they are part of the requested operation.

15 · Protection

Security

  • Default binding is 127.0.0.1; remote mode is explicit and fail-closed.
  • Remote mode requires strong bearer profiles and built-in TLS or a trusted HTTPS proxy.
  • Forwarding headers are accepted only from a loopback peer; the last forwarded address must be a valid IP, and the supplied Nginx template overwrites client headers.
  • User/admin authorization, owner-isolated jobs, per-user active-job quotas, rate limiting, and failed-authentication blocking are enforced by the API.
  • Administrative actions are available in the panel audit and emitted as sanitized JSON logs.
  • Only recognized HTTPS pages are accepted.
  • The CDN must match the provider.
  • The browser never receives signed URLs; it uses selections and UUID references.
  • CDN tokens are not written to jobs.json.
  • Local uploads have format, size, duration, range, codec-combination, and output-profile limits; names and paths are generated with UUIDs.
  • x-vdownloader-upload, x-vdownloader-audio, and x-vdownloader-audio-join block simple uploads initiated by another page.
  • Join metadata is capped at 64 KiB, every byte count is exact, and media streams directly to disk.
  • Incomplete uploads are removed, and every complete source is deleted with its job.
  • The proxy revalidates every media segment.
  • Security headers include CSP, frame denial, no-referrer, permissions restrictions, and HSTS only under verified HTTPS.
  • FFmpeg runs without a shell, from the job directory, with a reduced environment.
  • deploy/systemd/vdownloader.service runs as an unprivileged account, makes system/application paths read-only, restricts capabilities, and allows writes only to the job directory.

Linux starting templates and exact ownership steps are maintained in deploy/README.md, deploy/systemd/vdownloader.service, and deploy/nginx/vdownloader.conf. Validate them with representative media on the target distribution.

Private-server boundary. Configuration-based profiles are not a complete public account system. Internet exposure still requires a hardened identity or reverse-proxy layer, OS isolation, monitoring, backups, and security review.
Not hardened for public exposure. Before Internet exposure, add authentication, HTTPS, rate limiting, isolation, and monitoring.

16 · Support

Troubleshooting

High qualities do not appear

Review the HLS manifest and possible provider changes.

YouTube stopped analyzing videos

Update youtube-dl-exec to obtain a recent yt-dlp version: npm install youtube-dl-exec@latest. Private or sign-in-gated videos are not supported.

The job refreshes its link

The CDN link expired; the application automatically looks for a new URL.

Audio does not play

Choose AAC for MP4/MOV or Opus for WebM, and test the selected profile in a current player. H.265 and some MKV combinations are not supported by every browser.

The preview does not load

Check the /api/media/:id reference, network access, and regional restrictions. If the UUID expired, analyze the video again.

Storage is full

Delete jobs or increase MAX_STORAGE_GB.

The local file cannot be previewed

Convert the source to MP4/H.264 or try another browser. The application can export only files whose duration the browser can read.

The local upload is too large

Increase MAX_UPLOAD_GB without exceeding MAX_STORAGE_GB, or transcode the file before uploading it.

A local media export fails

Confirm every source has a browser-readable duration and a valid range. Audio joins allow at most 20 sources and 12 selected hours. Optional profiles require their FFmpeg encoders: libmp3lame, libvorbis, libopus, libx265, or libvpx-vp9. Run npm run test:e2e to exercise synthetic single-audio, joined-audio, and video-transcode journeys.

Remote requests through Nginx are unauthorized

Remote requests must include a configured bearer token. Keep Node on loopback and make Nginx overwrite X-Forwarded-For and X-Forwarded-Proto as shown in deploy/nginx/vdownloader.conf. Never turn proxied clients into the local administrator.

Restart returns access denied

For remote mode, use a token whose ACCESS_TOKENS_JSON profile has the admin role. For local-only mode, loopback is administrator access; if legacy ADMIN_TOKEN is configured, enter that value in the administrator token field.

The server reports too many requests

Normal polling remains below the default request budget. If HTTP 429 is still returned because several clients share one address or the configured budget is unusually low, job monitoring honors Retry-After, displays a temporary pause, and resumes automatically without marking the media job as failed.

18 · Reference

Glossary

AAC-LC
Compatible lossy audio codec used by MP4, MOV, MKV, and M4A profiles.
Bitrate
Approximate number of audio bits stored per second; higher values usually increase size and retained quality.
Codec
Algorithm that encodes or decodes a media stream, such as H.264, VP9, AAC, or Opus.
Container
File structure that holds streams, such as MP4, WebM, MKV, OGG, or M4A.
CDN
A network that delivers video files.
CORS
Browser restrictions between origins.
FFmpeg
The system tool that prepares video and audio outputs.
HLS
Streaming based on manifests and segments.
PCM
Uncompressed sampled audio used by WAV output.
Remux
Change the container without transcoding video.
Transcode
Decode a media stream and encode it using another format or profile.
SSRF
Malicious use of a server to query arbitrary destinations.
